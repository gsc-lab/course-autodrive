# 🚗 Capstone Design - Mini Autonomous Car

**영진전문대 글로벌시스템융합과 1학년 캡스톤디자인(I) 프로젝트**
카메라로 차선을 보고 스스로 달리는 **미니 자율주행 자동차**를 만듭니다 (Jetson Orin Nano).

이전 프로젝트 결과 영상: https://www.youtube.com/watch?v=0_gV1N-Q7Gw

## 🎯 목표

- 카메라 영상으로 차선을 따라 달리는 **자율주행 (Lane Keeping)**
- 팀별 확장 기능 (신호등 인식, 장애물 감지, 속도 제어 등)

## 🧭 전체 흐름

사람이 운전하며 찍은 사진으로 모델을 학습하고, 그 모델이 차를 운전합니다.

| 단계 | 프로그램 | 어디서 | 하는 일 | 결과물 |
|---|---|---|---|---|
| 1. 수집 | [collector/](collector/) | 차 (Jetson) | 패드로 직접 운전하며 사진을 찍습니다 | 세션 폴더 `dataset/<날짜_시각>/` |
| 2. 가공 | [curator/](curator/) | PC | 잘못 찍힌 사진을 빼고 데이터셋으로 묶습니다 | `dataset_<날짜_시각>.zip` |
| 3. 학습 | [trainer/](trainer/) | PC | 데이터셋으로 모델을 학습하고 시험합니다 | `models/<실행 이름>/` |
| 4. 자율주행 | 준비 중 | 차 (Jetson) | 학습한 모델로 차가 스스로 달립니다 | |

알아 둘 말 두 가지:

- **세션**: 한 번 주행하며 찍은 사진 폴더입니다. 사진 파일 이름에 그 순간의 조향 각도와 속도가 적혀 있고, 이것이 모델이 배울 정답입니다.
- **조향 단계** (`steering.classes`, 기본 30° 60° 90° 120° 150°): 모델이 고르는 답의 목록입니다. 프로그램 화면에서는 **클래스**라고 부릅니다.

## ▶️ 준비

### 차 (Jetson)

설치는 실습 자료를 따릅니다. 설치를 마친 차에 SSH 로 접속해 아래를 실행합니다.

```bash
cd ~/course-autodrive
git pull --autostash && uv sync         # 최신 코드 받기
bash scripts/jetson_setup.sh pair       # 처음 한 번: 내 패드 연결 (Share + PS 를 길게 눌러 라이트바가 빠르게 깜빡일 때)
```

### PC

[uv](https://docs.astral.sh/uv/) 를 먼저 설치합니다.

```bash
git clone https://github.com/gsc-lab/course-autodrive.git
cd course-autodrive
uv sync --extra gui --extra train       # NVIDIA GPU 가 있는 PC (수 GB)
uv sync --extra gui --extra train-cpu   # GPU 가 없는 PC 는 위 줄 대신 이것 (둘 중 하나만)
```

- `gui` 는 가공 프로그램, `train` 은 학습 프로그램입니다. **항상 한 줄에 함께** 적습니다. 하나만 적으면 다른 하나가 지워집니다.
- 최신 코드를 받을 때는 `git pull --autostash` 를 실행한 뒤 위의 `uv sync` 줄을 다시 실행합니다.

`--autostash` 는 내가 고친 `config.yaml` 을 지키면서 새 코드를 받는 옵션입니다. 받은 뒤 프로그램이 `[설정 오류]` 를 내면 그 안내대로 파일을 되돌리고 값을 다시 적습니다.

## 📷 1단계: 수집 (차)

```bash
uv run python -m collector --check      # 점검: 카메라, 보드, 패드. 서보가 가운데로 한 번 움직이면 정상
uv run python -m collector              # 수집 시작
```

○ 를 눌러 촬영을 켜면 **앞으로 달리는 동안** 사진이 저장됩니다. 멈춰 있거나 후진할 때는 저장되지 않습니다.

### 패드 조작 (DualShock 4)

| 조작 | 동작 |
|---|---|
| 왼쪽 스틱 좌우 | 조향 (D패드 ←→ 는 한 단계씩) |
| R2 | 전진. 당긴 깊이에 따라 3단계 속도, 놓으면 정지 |
| L2 | 후진 |
| ○ | 촬영 시작 / 정지 |
| □ | 방금 3초를 불량으로 표시 (실수한 직후에 누르기) |
| △ | 조향 중앙 |
| Options | 종료 |

### 차의 상태 표시 (도트 매트릭스)

| 화면 | 뜻 |
|---|---|
| ○ | 패드 연결됨, 촬영 안 함 |
| ● 과 ○ 가 번갈아 | 촬영 중 |
| X | 패드 연결이 끊기는 등 문제가 생겨 멈춤 |
| 꺼짐 | 수집 프로그램이 실행 중이 아님 |

### ⚠️ 안전 수칙

- 차에는 전원 스위치가 없습니다. 차가 말을 듣지 않으면 **구동 배터리 커넥터를 뽑습니다.**
- SSH 가 끊겨도 차는 패드로 계속 움직입니다. 끝낼 때는 반드시 **Options 버튼**을 누릅니다.
- `config.yaml` 의 `deadman` 을 `true` 로 바꾸면 **L1 을 누르고 있는 동안만** 달립니다.

### 사진을 PC 로 옮기기

세션 폴더를 통째로 PC 의 `dataset/` 폴더로 가져옵니다 (USB 메모리로 옮겨도 됩니다). 사진은 git 에 올리지 않습니다.

```bash
# PC 에서 실행. IP 주소와 세션 이름은 자기 것으로 바꿉니다
scp -r gsc@192.168.50.119:~/course-autodrive/dataset/20261110_1906 ./dataset/
```

사진 파일 이름이 곧 정답이므로 **파일 이름과 폴더 구조를 손으로 바꾸지 않습니다.**

## ✂️ 2단계: 가공 (PC)

```bash
uv run -m curator dataset/20261110_1906     # 세션 폴더 열기 (여러 개를 함께 적어도 됩니다)
```

1. `←` `→` 로 사진을 넘기며 확인합니다 (`Space` 는 자동 재생).
2. 잘못 찍힌 사진(차선을 벗어난 순간, 잘못 꺾은 순간 등)은 `Delete` 로 뺍니다. `Insert` 로 다시 넣고 `Ctrl+Z` 로 되돌립니다. 원본 사진은 지워지지 않습니다.
3. 사진 위의 가로선 두 개를 끌어 **모델에 넣을 범위**를 정합니다. 어두운 부분이 잘려 나가고, 사진 아래의 "모델이 보는 사진"이 그 결과입니다. 이 범위는 데이터셋에 함께 저장되어 학습할 때와 차가 달릴 때 똑같이 적용됩니다.
4. **데이터셋 만들기**를 누르고 저장할 폴더를 고르면 `dataset_<날짜_시각>.zip` 이 만들어집니다.

- 운전 중에 □ 로 표시한 구간은 처음부터 빠져 있습니다.
- 조향 단계가 서로 다른 세션은 함께 열 수 없습니다. 조향 단계는 촬영할 때 차의 설정을 따르므로 PC 에서 맞출 필요는 없습니다.
- 단축키 전체는 `F1` 로 볼 수 있습니다.

## 🧠 3단계: 학습 (PC)

한 줄로 학습, 시험, 차에 실을 모델(ONNX) 만들기까지 이어집니다.

```bash
uv run -m trainer train dataset/dataset_20261110_1906.zip                           # 학습 → 시험 → ONNX
uv run -m trainer train dataset/dataset_20261110_1906.zip --name lr0.01 --lr 0.01   # 이름을 붙이고 학습률만 바꿔서
uv run -m trainer test models/<실행 이름>                                           # 시험만 다시
uv run -m trainer test models/<실행 이름> --data dataset/다른날.zip                 # 다른 날 찍은 데이터셋으로 시험
```

결과는 `models/<실행 이름>/` 폴더에 모입니다.

| 파일 | 내용 |
|---|---|
| `loss_curve.png` | 학습 곡선: 에폭마다 손실이 어떻게 변했는지 |
| `test_report.txt`, `confusion_matrix.png` | 시험 결과: 학습에 쓰지 않은 사진으로 잰 정확도와 클래스별 정밀도, 재현율, F1 |
| `test_predictions.csv` | 시험 사진마다의 정답과 예측 (어떤 사진을 틀렸는지) |
| `model.onnx`, `model_meta.json` | 차에 싣는 모델과 그 설명서 |
| `history.csv`, `model.pth`, `split.csv`, `train_config.json` | 에폭별 기록, PyTorch 가중치, 사진을 나눈 방법, 이번 학습의 설정 |

`test_report.txt` 의 **전체 정확도**는 바로 아래 줄의 **기준선**과 비교해서 읽습니다. 기준선은 가장 많은 각도 하나만 답해도 나오는 정확도입니다. 전체 정확도가 기준선과 같으면 아무것도 배우지 못한 것입니다.

- **설정 바꾸기**: 학습 설정은 PC 의 [config.yaml](config.yaml) 2부(`training`)에 있습니다. 값을 **하나만** 바꿔 다시 학습하고 `loss_curve.png` 와 `test_report.txt` 를 비교합니다. `--lr`, `--epochs`, `--batch-size`, `--model` 은 명령에 바로 적을 수 있습니다.
- **zip 여러 개**: 여러 개를 적으면 합쳐서 학습합니다. 단, 같은 세션으로 만든 zip 끼리, 자르는 범위나 조향 단계가 다른 zip 끼리는 함께 쓸 수 없습니다.
- **`test --data`**: 준 zip 에 학습에 쓴 사진이 들어 있으면 몇 장인지 `주의:` 로 알려 줍니다. 이미 본 사진으로 시험하면 정확도가 실제보다 높게 나오기 때문입니다.
- **코드 읽는 순서**: [trainer/](trainer/) 의 `split.py` (나누기) → `data.py` (데이터) → `models.py` (모델) → `losses.py` (손실) → `optim.py` (옵티마이저) → `engine.py` (학습 루프). 학습이 진행되는 순서와 같습니다. 새 모델은 `models.py` 에 만들어 `MODELS` 에 등록하고 `training.model` 에 이름을 적습니다.

## ⚙️ 설정 (config.yaml)

바꿀 수 있는 값은 [config.yaml](config.yaml) 한 파일에 모여 있고, 값마다 설명이 적혀 있습니다. 이 파일은 차와 PC 에 하나씩 따로 있으므로 **그 값을 쓰는 쪽의 파일**을 고쳐야 합니다.

| 부분 | 내용 | 고치는 곳 |
|---|---|---|
| 1부 데이터 수집 | 조향 단계, 속도 단계, 사진 저장 간격, 카메라 노출 | 차 (SSH 로 접속해서) |
| 2부 모델 학습 | 모델에 넣는 사진 크기, 학습 설정 | PC |

값을 잘못 적으면 프로그램이 시작할 때 `[설정 오류]` 로 어디가 틀렸는지 알려 줍니다.
